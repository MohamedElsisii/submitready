Prepare this manuscript for submission: $ARGUMENTS

1. **Lock first.** If there is no lock for this manuscript, run `/lock` on it before anything else.
2. **Read the live guidelines.** Find the journal's official author guidelines and article-type pages. Read them now, even if a snapshot exists in `journals/requirements/`. Use the built-in web fetch first. Use a paid connector (for example a scraping service) only if the built-in fetch fails, and say so. A read only counts if you got the page text. If a fetch returns very little (a redirect, an error page, or under about 2,000 characters), the read failed: follow the redirect or try again, and if it still fails, tell the user plainly. Never say the live page matches a snapshot unless you read it in this run. If you got only part of a long page, fetch it again and ask only for the rules you still need (for example competing interests, data availability), quoted word for word. Mark a rule "not verified" only after that also fails. Tell the user, for each page, whether it was read and roughly how much text you got. If the page answers with a JavaScript or bot challenge ("enable JavaScript", "client challenge"), or the journal's numbers only load with scripts, and Claude in Chrome tools (`mcp__claude-in-chrome__*`) are available, open the page in a new tab, read it with `get_page_text`, and close the tab. Only read: never sign in, submit forms or accept anything beyond necessary cookies. If a page still cannot be read, ask the user to open it and paste the text. Never fill gaps from memory.
3. **Write the requirements file** as `<manuscript>_<journal>.requirements.json` next to the manuscript (same format as the files in `journals/requirements/`). Start from the newest snapshot for this journal in `${CLAUDE_PLUGIN_ROOT}/journals/requirements/`, not from a requirements file left by an earlier run, because the snapshot may have fixes the old file lacks. Then update it from the live read: one entry per rule, with the exact quoted sentence where possible (leave `quote` empty if you paraphrased), the source URL and today's date. Use a measurable `check` type when one fits (the list is in the docstring of `check()` in `scripts/prepare.py`); otherwise `manual`. Find the journal's CSL style in the CSL styles repository and record its id and URL.
4. **Check:** `python "${CLAUDE_PLUGIN_ROOT}/scripts/prepare.py" check <manuscript.docx> <requirements.json> --report <manuscript>_<journal>_checklist.md`. Exit code 1 means some rules need fixing; it is not a failure.
5. **Format (layout only):** `python "${CLAUDE_PLUGIN_ROOT}/scripts/prepare.py" format <manuscript.docx> <requirements.json> --out <manuscript>_<journal>.docx`
6. **Prove it:** `python "${CLAUDE_PLUGIN_ROOT}/scripts/lock.py" verify <lock.json> <manuscript>_<journal>.docx --report <manuscript>_change_report.md`. Show the PASS/STOP line.
7. Summarize for the user: what was fixed automatically, what they must fix (with the guideline quote), which reference style to pick in their reference manager, and the "check yourself" items. Never edit manuscript text.
