Prepare this manuscript for submission: $ARGUMENTS

1. **Lock first.** If there is no lock for this manuscript, run `/lock` on it before anything else.
2. **Read the live guidelines.** Find the journal's official author guidelines and article-type pages. Read them now, even if a snapshot exists in `journals/requirements/`. Use the built-in web fetch first. If the built-in fetch fails, try Claude in Chrome (below). Never use a paid tool (a scraping connector such as Firecrawl, or any service that bills per page or per call) unless the user said yes to it in this conversation. Ask once, say it may cost money, and offer the free ways first: Claude in Chrome, or the user pasting the page text. A read only counts if you got the page text. If a fetch returns very little (a redirect, an error page, or under about 2,000 characters), the read failed: follow the redirect or try again, and if it still fails, tell the user plainly. Never say the live page matches a snapshot unless you read it in this run. If you got only part of a long page, fetch it again and ask only for the rules you still need (for example competing interests, data availability), quoted word for word. Mark a rule "not verified" only after that also fails. Tell the user, for each page, whether it was read and roughly how much text you got. If the page answers with a JavaScript or bot challenge ("enable JavaScript", "client challenge"), or the journal's numbers only load with scripts, and Claude in Chrome tools (`mcp__claude-in-chrome__*`) are available, open the page in a new tab, read it with `get_page_text`, and close the tab. Only read: never sign in, submit forms or accept anything beyond necessary cookies. If a page still cannot be read, ask the user to open it and paste the text. Never fill gaps from memory. Then check the saved snapshot against what you read: save each page's text into a folder (the file name comes from `python "${CLAUDE_PLUGIN_ROOT}/scripts/freshness.py" --key <url>`) and run `python "${CLAUDE_PLUGIN_ROOT}/scripts/freshness.py" --only <snapshot name> --cache <folder> --report <folder>/freshness.md`. Every rule it lists as changed must come from the live page, not the snapshot; tell the user which ones.
3. **Write the requirements file** as `<manuscript>_<journal>.requirements.json` next to the manuscript (same format as the files in `journals/requirements/`). Start from the newest snapshot for this journal in `${CLAUDE_PLUGIN_ROOT}/journals/requirements/`, not from a requirements file left by an earlier run, because the snapshot may have fixes the old file lacks. If the journal has no snapshot, run `python "${CLAUDE_PLUGIN_ROOT}/scripts/families.py" find "<journal name>" --publisher "<publisher>" --url "<journal home page>"` (the publisher is on the journal's site or in the finder's table). It looks in `${CLAUDE_PLUGIN_ROOT}/journals/families/`: a family file either lists journals that share one guidelines document (for example the 24 Expert Medicine journals of Taylor & Francis) or matches a publisher whose journals share one template (for example MDPI). Use the family's `journal_specific` list: those rules must come from the journal's own page. Start from the family snapshot, still read the family guidelines and the journal's own page live, and add the journal's own rules. If neither exists, build the file from the live read alone; every journal is supported this way. Then update it from the live read: one entry per rule, with the exact quoted sentence where possible (leave `quote` empty if you paraphrased), the source URL and today's date. Use a measurable `check` type when one fits (the list is in the docstring of `check()` in `scripts/prepare.py`); otherwise `manual`. Measurable means the script can count it: word limits, keyword counts, sections and their order, a structured abstract's headings (`abstract_structure`), heading levels, figure caption style (`caption_style`), font (`font`, with `strict` only when the guideline says "must" rather than giving an example), DOIs as links (`doi_format`), supplementary label style (`supp_label_style`, including "Online Resource 1"), and supplementary file names and formats (`supp_files`, one rule with `name_pattern`, `name_example` and `formats`). Then check every quote against the saved page text with `python "${CLAUDE_PLUGIN_ROOT}/scripts/freshness.py" --file <requirements.json> --cache <folder>`. A quote it reports missing is not word for word: copy it again from the page, or leave `quote` empty. Never describe a missing quote as "the same wording" without that run. Find the journal's CSL style in the CSL styles repository and record its id and URL. Then compare it with the guidelines' own reference rules and example (for example "list all authors where there are fewer than four" means `et-al-min="4"`). A journal's dependent style can be years old: if its parent style disagrees with the current guidelines, use a style that agrees (often the publisher's current style) and say why in the `csl_style` note.
4. **Check:** `python "${CLAUDE_PLUGIN_ROOT}/scripts/prepare.py" check <manuscript.docx> <requirements.json> --report <manuscript>_<journal>_checklist.md`. Exit code 1 means some rules need fixing; it is not a failure.
5. **Format (layout only):** `python "${CLAUDE_PLUGIN_ROOT}/scripts/prepare.py" format <manuscript.docx> <requirements.json> --out <manuscript>_<journal>.docx`
6. **Prove it:** `python "${CLAUDE_PLUGIN_ROOT}/scripts/lock.py" verify <lock.json> <manuscript>_<journal>.docx --report <manuscript>_change_report.md`. Show the PASS/STOP line.
7. Summarize for the user: what was fixed automatically, what they must fix (with the guideline quote), which reference style to pick in their reference manager, and the "check yourself" items. Never edit manuscript text.
